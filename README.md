# 다판다 마켓 — Clearance-sale

중개판매와 플랫폼 직접판매를 결합한 전국 상품·재고 유통 플랫폼 다판다의 **시제품**입니다. 거래 구조를 검증하며, 실제 주문·결제·정산은 하지 않습니다.

## 실행
로컬 서버가 필요합니다. 모듈 스크립트라 `index.html`을 파일로 열면 동작하지 않습니다.

```bash
python -m http.server 8765
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. Netlify는 배포 디렉터리를 `.`으로 연결합니다. 별도 빌드는 없습니다.

운영 금지 게이트:

```bash
node scripts/production-gate.mjs
```

`CLEARANCE_PRODUCTION_RELEASE=1`이면 게이트는 항상 실패합니다.

## 현재 구현
- 예시 상품 6개, 카테고리·검색, 해시 라우팅, 상세 대화상자
- 상품 스키마: id, channel, sellerOfRecord, sellerId, qtyOnHand, qtyReserved, condition, region, status
- 판매가능 수량 = 보유 − 예약. 화면은 표시만 하고 재고를 차감하지 않음
- 주문 스냅샷 초안: 법적 판매자·채널·책임 주체를 고정해 보여 주되 executable=false
- 입점 신청 시뮬(id/시각/상태, 최대 20건), 로컬 승인·반려. 상품 목록에 반영하지 않음
- 여정 8단계 설계 표, 할인율 가드, OS 테마, noindex
- 구매·결제 버튼 없음

## 운영 금지
- 인증/인가, 서버 DB, 사업자 검증, PG, 원자적 재고 예약·차감, 취소·환불, 정산, 판매자별 접근통제, 감사로그 **미구현**
- 샘플 상품/가격은 가상 정보. 고객 개인정보를 수집하지 말 것
- 데모 관리 화면은 인증된 관리자가 아님
- 대표 브랜드 **다판다**, 슬로건 **빠른 판매, 좋은 상품, 합리적인 가격**
- 등록 도메인: 대표 **www.다판다.store**, 추가 **www.다판다.shop**. DNS 변경은 사용자 완료 기준이며, 호스팅 연결·HTTPS·리디렉션은 별도 확인 필요
- 대표 주소는 등록 순서를 기준으로 선정. 데모 단계에서는 canonical 및 자동 리디렉션을 강제하지 않음

## 개발 순서
1. 상품·판매자 데이터 구조 (진행 중)
2. 고객 화면: 상세, 라우팅, 접근성, 재고 표시
3. 입점 시뮬과 실제 관리자 기능 분리
4. Intent DNA 8단계 상태 흐름 정의. 미구현은 처리된 것처럼 표시하지 않음
5. 운영 전: 실명 고지, 약관, 인증, 결제, 정산, 감사, 배포 게이트 통과 후에만 공개 운영 판단

공개 주소가 생겨도 데모 안내와 noindex를 유지하고, 실제 거래는 운영 검증 전까지 비활성입니다.

### 모바일 진입영상 재생 보완

- 움직임 줄이기에서는 자동 재생하지 않되, 다시 보기에서 사용자가 직접 재생할 수 있습니다. 재생 성공 또는 명시적인 건너뛰기 후에만 방문 완료를 저장합니다.
- 포스터 이미지와 10초 시작 대기, 최대 26초 재생 상한을 적용합니다. 정식 도메인의 이전 배포는 PR 병합과 Git 연결 배포로 교체합니다.

## 상품 3단계 분류와 입점업체
- 모든 상품은 **대분류 → 중분류 → 소분류**의 3단계로 분류합니다. 브랜드·입점업체·상품 상태·가격은 별도 필터입니다.
- 분류 원본은 `js/taxonomy.mjs`입니다. 홈과 남성복 화면이 같은 원본을 사용하며 상위 선택 변경 시 맞지 않는 하위 선택을 해제합니다.
- 대분류 12개: 남성복, 여성복, 신발, 액세서리, 시계, 귀금속, 가전, 가구·인테리어, 생활·주방, 식품·농산물, 공구·산업용품, 스포츠·레저.
- 예: **남성복 → 바지 → 슬랙스**, **남성복 → 슈트 → 투피스 슈트**, **신발 → 운동화 → 러닝화**. 운동화·구두는 신발의 중분류이며 홈에 바로가기도 제공합니다.
- 무신사·SSG의 상품 카테고리 탐색 방식을 참고해 다판다의 3단계 구조로 구성했습니다. 참고: https://www.musinsa.com/category / https://www.ssg.com/ . 특정 업체의 분류표나 디자인을 복제하지 않았습니다.
- 남성복 대분류 `/#/menswear`에서 9개 중분류를 선택하고, `/#/menswear/clothing?major=menswear&middle=pants&minor=slacks`에서 소분류와 입점업체를 선택합니다.
- 입점업체 **비버리힐스 폴로 / 이원재 / TOP GUN**은 `/#/menswear/clothing/vendor/{vendorId}`에 분리합니다. 선택한 분류를 URL로 유지하며 해당 업체 상품만 표시합니다.
- 실제 업체 상품 자료가 없어 업체별 목록에는 준비 안내를 표시합니다. 가상 예시는 `/#/menswear/samples` 및 `/product/{productId}`에 분리하고 실제 업체 경로에서는 조회를 차단합니다.
- 23개 기존 예시 상품 모두 유효한 소분류에 연결했습니다. 분류/가격/상태/재고/검색/정렬은 URL 쿼리로 유지되며 사이즈는 선택 체험, 관심상품은 브라우저 저장만 지원합니다.
- 이전 `/#/menswear?vendor=...`와 `/#/menswear/product/...` 공유 링크는 정규 경로로 전환합니다.
- 검증: `node --test tests/menswear-data.test.mjs tests/taxonomy.test.mjs`; Playwright 환경에서 `node tests/menswear-browser.cjs`. 브라우저 경로 지정은 `DAPANDA_CHROMIUM_EXECUTABLE` 환경변수를 사용합니다.
- 320/390/768/1440px에서 분류 변경, 3개 업체, 예시 분리, 필터·정렬·관심상품·사이즈, 상세 복귀, 이전 링크, 입력 이스케이프와 다크 모드를 검사합니다.

## 입점·상품 등록 한도
- `js/capacity.mjs`: 전체 입점업체 최대 100개, 업체별 상품 최대 50개. 기존 남성복 업체 3개가 전체 정원에 포함됩니다.
- 심사 대기와 승인 업체는 정원을 사용하고 반려 시 반환합니다. 반려 업체 재승인 시에도 한도를 재검사합니다. 동일 이름의 중복 신청은 차단합니다.
