# 다판다 라이브·스튜디오 — 조사 및 구현 범위

확인일: 2026-11-01 (한국 시간). 실제 방송 채널·공간·장비를 임의로 생성하거나 운영 중이라고 표시하지 않는다.

## 채택한 운영 방식

OBS 촬영/인코딩 → 운영자의 YouTube Live 채널 → 다판다의 공식 임베드 플레이어.
서버는 스튜디오 예약·업체 계약 검증·견적 동의·편성·준비 점검을 담당하며 영상 인코딩·RTMP 수신을 Netlify Functions에서 처리하지 않는다.
유료 방송 인프라 계정 생성이나 장비 구매는 하지 않았다.

| 방식 | 활용 | 이번 적용 |
| --- | --- | --- |
| YouTube Live + OBS | 기존 채널로 방송하고 사이트에서 공식 플레이어로 시청 | 방송 URL 연결·편성 관리·실제 API 상태 대조 구현 |
| Amazon IVS | 플랫폼 자체 저지연 플레이어·채팅을 별도 구성할 때 | 조사만 수행, AWS 채널/비용 발생 없음 |

YouTube Live Streaming API는 OAuth로 방송·스트림을 생성/연결/전환하는 기능을 제공한다. 이번 구현은 운영자가 YouTube Studio에서 직접 송출한 방송 URL을 연결하므로 OAuth 토큰·송출 키를 사이트에 수집하지 않는다.
YouTube 모바일 웹의 채팅 임베드는 지원되지 않아 모바일은 YouTube 시청·채팅 링크를 제공한다. 데스크톱 채팅은 사용자가 열 때 현재 도메인의 embed_domain으로 연결한다.

## 구현 기능

- `/live.html`: 공개 방송 편성·다시보기, 등록된 스튜디오·장비 안내, 개인정보를 제외한 확정 예약 시간표.
- 홈페이지와 계약·정산센터에서 라이브·스튜디오로 이동 가능.
- 업체: 유효한 서명 계약으로 예약 신청, 관리자 견적의 금액·조건·버전에 동의한 뒤 확정, 본인 예약과 편성 초안 관리.
- 이용 종료 후 관리자가 장비·공간 반환을 확인하고 예약을 마감한다. 공개 편성·방송이 남아 있으면 마감할 수 없다.
- 관리자: 실제 공간·장비·준비 간격 등록/수정, 제작·대관비 견적, 방송 사전 점검·공개·방송중/종료 확인.
- 확정 예약과 준비 간격의 충돌 방지. 견적 제시만으로 시간 독점 또는 결제 완료가 되지 않으며, 확정 시 충돌을 다시 대조한다.
- 예약은 15분 이후 시작, 30분~8시간. 업체당 미확정 예약은 최대 10개.
- 스튜디오 이용료는 별도 견적·청구서로 Toss PG 승인·전액 취소와 대조한다. 플랫폼 상품 판매 수수료·입점업체 판매대금 정산 원장과 합산하지 않는다.
- 방송별 공식 YouTube 주소, 진행/송출 담당자, 소개 상품 최대 8개와 외부 판매 페이지·이미지·안내 가격을 관리한다.
- 소개 상품 링크는 관리자가 직접 대조한다. 기존 쇼핑몰 카탈로그는 여전히 시제품이므로 이 기능으로 주문·결제를 개통했다고 표시하지 않는다.
- 사전 점검: 장비, 네트워크/리허설, 출연·촬영·상품 이미지·음원 권리, 상품·가격·링크, 담당자.
- 아르카온 규칙 엔진은 서명 계약·업체 상태·예약 확정·송출 주소·준비 항목을 확인한다. 미비하면 HOLD와 항목별 수정 안내를 반환한다. 모델 학습이나 LLM 검토를 수행했다고 주장하지 않는다.
- 초안은 비공개. 관리자가 확인한 편성만 공개하고, 편성 정보 수정 시 다시 초안으로 전환해 점검을 받는다.
- 방송중은 운영자의 YouTube 관제 확인과 실제 API 검증을 함께 거친 상태이며 실제 YouTube 송출을 자동 시작/종료하는 버튼이 아니다. 예약 시간을 벗어나 오래 남은 LIVE는 공개 화면에서 '종료 확인 중'으로 바꿔 표시한다.
- 시청자가 플레이어를 열거나 YouTube 시청 링크로 이동하면 사이트 배경음악을 정지한다. YouTube 재생 UI·브랜딩은 숨기지 않는다.
- 다시보기는 별도 공개 동의한 종료 방송만 제공한다. 원본 영상 공개·외부 재생 허용 상태는 YouTube 운영자가 관리한다.
- 모든 변경은 기존 내부 운영 시스템의 감사 해시 이력에 연결된다. 방송 관련 기능이 계약·정산 원본을 덮어쓰거나 지급을 실행하지 않는다.

## 실제 개설 전 운영자가 준비할 항목

1. 기존 계약·정산센터의 Identity 활성화, 운영자 dapanda-admin 역할, 입점업체 계정·계약 검증. 역할 변경은 다음 로그인/토큰 갱신부터 반영된다.
2. 실제 스튜디오명·위치·보유 장비·이용 시간과 제작/대관 견적·취소 조건을 등록한다.
3. 운영할 YouTube 채널에서 라이브 기능과 외부 임베드를 허용하고 시험 방송을 수행한다. 첫 라이브 활성화에는 대기 시간이 있을 수 있다.
4. OBS에서 실제 회선·장비를 대상으로 자동 구성 마법사와 리허설을 진행한다. 카메라/캡처 입력, 마이크, 조명, 녹화 저장, 유선 회선, 비상 화면을 확인한다.
5. 출연 동의, 상품 설명/가격/이미지 권리, 사용할 방송 음원의 권리를 확인한다. 사이트 BGM 파일 업로드가 방송 재송출 권리를 자동 보증하지 않는다.
6. 실제 상품 등록·주문·PG 검증, 취소·반품·지급 연동은 기존 시제품의 후속 과제다. 상품 링크 안내를 실제 플랫폼 결제 완료로 설명하지 않는다.

## 검증

`npm run test:live`, `npm run test:operations`, `npm run check`, `npm run build`.
테스트 DB에서 견적 버전·권한·중복/준비 간격·공개 전 점검·편성 수정·상태 전이·감사 이력을 검증한다.
실제 YouTube 채널 송출, 실장비 리허설, 실제 사용자 인증과 방송 음원 권리 검토는 별도이며 테스트 성공으로 대체하지 않는다.

## 2026-11-01 운영 보강: 외부 PG·실제 방송 상태 검증

이번 보강은 **스튜디오 이용료**에 한정한다. 쇼핑몰 상품 주문·재고·배송·판매대금 정산을 개통한 것으로 설명하지 않는다.

### 계정·키 연결 (Netlify Functions 환경 변수)

| 이름 | 의미 |
| --- | --- |
| `STUDIO_TOSS_CLIENT_KEY` | 토스페이먼츠 API 개별 연동 일반결제 클라이언트 키 (`test_ck_` / `live_ck_`) |
| `STUDIO_TOSS_SECRET_KEY` | 같은 상점·모드의 시크릿 키. 서버 전용, 채팅·소스·공개 파일에 저장 금지 |
| `STUDIO_LIVE_PAYMENTS_ENABLED` | 실결제 전환 시에만 `true`. 운영 배포에서만 실결제 허용 |
| `YOUTUBE_DATA_API_KEY` | YouTube Data API v3 활성화한 서버 키. 해당 API로 제한 |
| `STUDIO_YOUTUBE_CHANNEL_ID` | 실제 운영 채널 ID (`UC…`), 다른 채널 방송은 공개 점검 탈락 |

키는 Netlify 대시보드의 Functions 범위에 입력하고 재배포한다. Preview는 실결제가 차단된다. 키 형식·모드 일치는 검증하지만 발급된 키 쌍이 동일 MID인지 최종 확인은 실제 PG 테스트 승인으로 검증한다. Identity 활성화 및 `dapanda-admin` 지정은 별도로 필요하다.

### 실제 실행 흐름

1. 관리자가 공간·장비 등록 → 업체의 서명 계약으로 이용 신청 → 관리자가 견적 총액·VAT·취소 조건 제시 → 업체가 최신 견적에 동의.
2. 업체가 이용료 결제를 시작하면 서버가 확정 견적을 불변 청구서에 복사한다. 브라우저가 금액을 지정할 수 없다. 유상 금액 1~100,000,000원, 카드/간편결제 통합결제창을 사용한다. 0원 무상 견적은 PG를 호출하지 않는다.
3. 공식 Toss V2 SDK에서 결제수단 인증 후 돌아오면 업체가 ‘견적 대조·승인 확인’을 실행한다. 서버가 업체 소유권·예약 상태·견적·금액·주문번호를 대조하고 승인 API를 호출한다. 리다이렉트 성공만으로 승인 완료로 처리하지 않는다.
4. 외부 승인 전에 DB에 승인 의도를 저장하며 청구별 동일 멱등키를 재사용한다. PG 응답이 끊기면 결과를 조회한다. 미확정 청구는 예약 취소를 막고 재조회로 복구한다. PG가 승인 전 상태인 경우 저장된 승인 의도를 동일 멱등키로 재시도한다. 이용 시작 후 새 승인은 하지 않는다.
5. 관리자만 사유·전액 취소 동의를 기록하고 환불을 실행한다. 방송중/공개 편성을 먼저 종료·취소해야 한다. PG에서 전액 취소와 잔액 0을 확인한 후 예약을 취소한다. 통신 오류 시 환불 대기로 남고 같은 취소 멱등키로 복구한다. 부분 취소·위약금 공제·가상계좌 환불계좌 수집은 지원하지 않는다. PG 콘솔에서 부분 취소가 감지되면 자동 마감하지 않고 관리자 대조를 요구한다.
6. 업체·관리자는 PG 결과 재조회, PG 전표, 서버 청구 원본에 기반한 이용료 명세서 출력/PDF 저장을 사용할 수 있다. 명세서는 세금계산서가 아니다. 카드번호·계좌번호는 사이트가 수집하지 않는다. 테스트 거래와 실거래를 명확히 분리한다.
7. 실결제 청구 생성 전 같은 운영 DB에 테스트 승인 후 전액 취소 완료 기록이 있어야 한다. 테스트 키로 전체 흐름을 먼저 실행하고, PG 계약·상점 확인 후 운영 키와 실결제 플래그로 재배포한다. 기존 미결 테스트 청구는 테스트 모드에서 정리한다.
8. 방송 편성 공개/방송중 전환 시 2분 이내 YouTube API 검증이 필수다. 운영 채널, 공개 또는 일부공개, 임베드 허용, 실제 예정/진행 상태를 대조한다. 유상 예약은 실제 운영 PG 승인도 필수이며 테스트 승인으로 공개할 수 없다.
9. 스케줄러가 2분마다 방송 상태(최대 50건, 일괄 API 조회)와 결제·환불 상태(최대 2건)를 재검증한다. 거래 목록은 오래 조회하지 않은 순서로 처리한다. 관리자도 즉시 재조회 가능하다. 방송 검증이 5분을 넘거나 실방송 상태가 아니면 공개 LIVE 배지를 ‘송출 상태 재확인’으로 낮춘다. 스케줄러는 OBS/YouTube 송출을 시작하지 않는다.
10. 관리자 화면은 API/PG 설정과 테스트 승인·취소 기록, 확인 중 결제·환불 건수를 표시한다. ‘설정됨’과 실제 외부 리허설 통과는 다르다.

### 인수 테스트와 개설 판정

- SQL+DOM+서버 테스트: 금액·소유권 변조, 중복 승인, 응답 유실 복구, 재시작 후 대조, 관리자 환불, 견적 고정, 미결제 편성 차단, API 검증·LIVE 노후화.
- 위 테스트는 테스트 대역을 사용한다. 실제 PG·YouTube·Identity 접속 성공을 대신하지 않는다.
- 실제 운영 인수는 **관리자/업체 각 계정 로그인 → 서명 계약 → 예약/견적 → 테스트 결제/전액 취소 → 운영 키 소액 승인/취소 → 실장비 시험 방송/임베드/모바일 확인**이 끝나야 한다.
- 운영 상점·채널·실장비가 아직 제공되지 않았다. 실제 외부 인수 테스트는 미완료이며 전체 플랫폼 운영 완료로 판정하지 않는다.
