# 결정 기록: 플랫폼 호스팅 판매자 전용몰 ONLY

상태: 사업모델 확정 / 코드 구현·실운영 미완료

## 선택
땡처리가 각 입점업체의 상품 상세, 전체 카탈로그, 장바구니, 주문, 체크아웃을 직접 호스팅한다. 예시 URL: `/shops/{seller_slug}`. 판매업체는 승인 후 자신의 몰에 상품을 등록·관리한다. 메인 마켓에는 대표상품을 노출하고 '더보기'는 **땡처리 내부 판매자 전용몰**로 이동한다.

## 제외
외부 쇼핑몰 결제 강제, 외부몰 결제 플러그인, 외부몰 결제 귀속 추적, 외부 쇼핑몰 설치·업로드는 **구현 범위에서 제외**한다. 기존 외부몰 링크는 선택적 안내용이며 외부 거래는 땡처리 결제·수수료 대상이 아니다. 이전 `docs/external-storefront-checkout.md`는 대안 검토 기록으로만 보존하고 이 결정이 우선한다. 해당 문서의 외부몰 연동 필수동의는 적용하지 않는다.

## 핵심 흐름
SELLER_APPLIED → SELLER_APPROVED → PG_OFFERING_SELECTED → PG_MERCHANT_APPROVED → PG_CONNECTION_ACTIVE → SELLER_SHOP_PUBLISHED → PRODUCT_LISTED → CART → ORDER_CREATED → PG_PAYMENT_VERIFIED → FULFILLMENT → REFUND/SETTLEMENT.

## 아키텍처
- 테넌트 분리: seller_id 기반 권한, 상품·주문·계약·결제·정산 전부 서버에서 소유권 검증.
- 쇼핑몰: 공유 코드베이스 + 판매자별 로고/배너/테마/배송·교환 정책, 독립 상품 목록, 검색, SKU·옵션·재고.
- 결제: PG사는 땡처리에 입점하고 판매자가 승인된 PG 상품을 선택. PG별 공통 서버 커넥터는 아르카온이 제안·시험하고 에테르니언 감사 후 운영자가 배포.
- 주문: 구매금액·재고·배송비 서버 검증, 재고예약/취소·결제 멱등성, 주문별 seller-of-record/PG/계약 버전 스냅샷.
- 장바구니: 우선 단일 판매자 결제. 여러 판매자 상품은 주문·결제를 판매자별 분리.
- 정산: PG사와 판매자의 실제 계약·가맹점 구조에 따라 직접 정산 또는 승인된 지급대행을 구분. 땡처리 중개수수료는 별도 원장·청구로 처리.
- 관리: PG사 입점 심사, 판매자 계약/수수료, 상품 심사, 민원/환불, 재무 대사, 감사로그.
- 개인정보/보안: 실제 회원 인증, RBAC, 서버 세션, 비밀저장소, PG 웹훅 검증, 개인정보 처리방침, 전자상거래 표시 의무.

## 아르카온 개발 범위
1. 모바일 우선 판매자 전용몰 공통 템플릿 및 입점/관리자 UI.
2. 인증·DB·판매자/PG사 가입과 심사·계약·상품/재고 관리.
3. PG사별 공통 어댑터와 샌드박스 테스트.
4. 주문·환불·수수료·정산 원장 및 오류복구.
5. CI 보안/회귀 테스트, 단계별 출시 증거, 에테르니언 감사 패킷.

## 출시 게이트
현재 저장소는 정적 데모다. 이 문서는 운영 가능한 구현을 뜻하지 않는다. PG 실계약, 가맹점 심사, 법적 고지, 보안/대사/환불/장애 시험, 감사 및 운영자 승인 전 결제 공개 금지.
